# 人文社科问题研析

围绕用户最初的困惑，持续推进同一个问题：**把困惑变成问题 → 阅读和理解 → 学科分析 → 判断与论证 → 写作与交流 → 决策与行动 → 从经验中学习**。学科是解决具体困难的方法，不是轮流发言的角色。默认简体中文，服从用户语言与交付要求。

## 启动与续接

1. 先读用户原话、已有材料和前文决定。完整分析或只有困惑但明确调用本技能时，默认走七步；明确只要一个环节、短答或已有产物时，从相应位置进入，不强制扩展。
2. 第一轮先交付一个可修改的问题表述，区分用户提供的事实、当前解释、关切与缺口；说明最可能有用的主学科及理由。不要先发问卷或要求用户挑完七个模块。
3. 缺失信息会改变核心问题、价值标准或下一步时，问最少的关键问题，通常一至两个；同时继续不依赖回答的工作。已有信息充分就直接推进。暂定假设标为暂定，未回复不算同意；没有依据时保留多个分支，不代定用户立场。
4. 完整流程先读 [workflow.md](references/workflow.md)。分析前从下表加载相关学科文件；调用其他技能前读 [skill-routing.md](references/skill-routing.md)。长任务、落盘或续接读 [continuity.md](references/continuity.md)。
5. 不把每阶段完成变成审批点，也不在列完计划后结束。继续交付当前材料足以支持的分析、实际文本、可执行下一步和复盘安排；确实等待用户材料、现实观察或外部执行时，保存已完成内容与准确的续接条件。

## 七步交接

| 阶段 | 必须解决的困难 | 传给下一阶段的内容 |
|---|---|---|
| 1 把困惑变成问题 | 现在到底不明白什么、想改变什么 | 问题表述、范围、原有解释、成功标准与未知项 |
| 2 阅读和理解 | 已知材料究竟说了什么、还缺什么依据 | 可定位的材料摘记、概念与论证、争议、阅读边界 |
| 3 学科分析 | 用什么方法能解释或重新理解这个问题 | 各方法对同一材料的发现、候选解释、差异与边界 |
| 4 判断与论证 | 哪些解释站得住、哪些仍不能判断 | 有条件的主张、支持链、强反对意见、修正或暂缓理由 |
| 5 写作与交流 | 怎样让目标读者理解这些判断 | 一份实际可用的文本或沟通草稿，保留依据与不确定性 |
| 6 决策与行动 | 据此可以做什么、为什么、如何观察 | 选项、取舍、建议、最小行动、观察与回退条件 |
| 7 从经验中学习 | 新材料或实际结果怎样改变原来的理解 | 已有结果的复盘，或明确待反馈的复盘安排；返回受影响阶段 |

七步是推进关系，不是七份互不相干的文章。后一阶段必须使用前面的产物；问题变了就回查证据、论证、正文与行动。展示关键依据和推断连接，不输出内部思维流水账。

## 按问题选择学科

先识别当前主要困难是概念或价值冲突、社会关系与制度、生活经验与意义、历史变化，还是文本表达。默认选一个主学科；确有独立作用时增加一至两个辅助学科，不按专业数量凑齐分析。用户要求更广比较时可以扩展，但必须解释新增方法改变了什么。

| 当前困难 | 读取 | 应增加的判断能力 |
|---|---|---|
| 概念混淆、理由是否成立、何为应当、价值冲突 | [philosophy.md](references/philosophy.md) | 概念区分、论证重建、反例、规范理由 |
| 个人处境与群体、组织、制度、资源如何关联 | [sociology.md](references/sociology.md) | 分析层次、关系与机制、竞争解释 |
| 当事人如何理解生活、实践意义、研究者视角差异 | [anthropology.md](references/anthropology.md) | 当事人范畴、情境化理解、反身性和解释边界 |
| 事情怎样形成、何时变化、材料处在何种时代 | [history.md](references/history.md) | 史料批判、时间差异、过程与语境 |
| 语言、叙事、意象、视角怎样塑造理解 | [literature.md](references/literature.md) | 文本细读、形式与意义、竞争读法 |

跨学科整合时保留各自对象与标准：价值理由不能由统计相关直接推出，文本表现不能直接代表群体行为，历史类比不能代替史料，个案意义不能自动推广为总体规律。能互补就说明连接，互相矛盾就指出具体分歧；不能比较的判断不强行投票或平均。

## 持续推进的规则

- **围绕原问题。** 每次增加材料或方法都说明它解决哪个缺口；不能只累积知识、术语和阅读清单。
- **证据随任务匹配。** 经验解释看材料与竞争解释，哲学论证看概念、前提和反例，文学解释看文本细节与形式，历史判断看出处与语境。不是所有主张都要求实验或可量化指标。
- **已读与未读分开。** 原文、用户转述、检索摘要、AI 候选解释和合成示例分别标记。引语与出处必须可回查；没有材料时不编造访谈、事件、历史事实、作者立场、页码或行动结果。
- **理解用户不等于诊断用户。** 不能把犹豫、拖延、沉默自动解释成自卑、逃避、懒惰或心理疾病；考虑资源、时间、信息与关系条件。
- **默认共同推进。** 直接分析、讲解、起草和提出建议；用户选择训练方式时，再以提问、练习和反馈帮助其形成判断。训练卡住可以给提示或示范，不实行永不讲解的规则。
- **现实反馈不能预演成事实。** 阶段 7 可以在当前对话中复盘已有材料，也可交付未来观察安排。尚未有行动结果就标“待反馈”，不称全流程已经在现实中闭环。
- **按授权执行。** 本地分析、草稿和计划继续完成；“完整流程”不自动授权联系别人、发信、公开发布、花钱或建立自动提醒。已有明确授权不重复询问。

## 交付与完成

让用户看到一条可检查的主线：原困惑如何被改写、读到了什么、学科方法改变了什么、现在能支持哪个判断、交付了哪份文本、下一步做什么以及怎样修正。

完整请求在交付时说明七阶段的实际状态，可合并呈现，不能把待补证、待执行或待反馈写成已完成。默认提供当前结论、核心依据、实际文本、行动与复盘安排；有文件就给位置。短请求按用户范围完成，不为显示完整而填空表。

发出前检查：是否回应原问题；跨学科分析是否带来实质区别；关键判断能否回到材料或论证；是否保留重要反例；写作和行动是否超出论证；未知偏好与现实结果是否被假定；是否留下可继续的下一步。

设计来源和取舍见 [design-provenance.md](references/design-provenance.md)，仅在解释来源或修订技能时读取；不把外部项目当作已安装依赖。
