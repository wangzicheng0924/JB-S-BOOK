# 状态记录与反馈续接

完整、多轮问题分析默认保存最少的可续接材料；用户明确不要文件时保留在对话中。优先沿用当前问题已有目录，不能仅因日期变化新建重复项目。已有论文或其他项目只补需要的状态，不另造平行档案。

无既定位置时可在当前可写工作目录的 `inquiries/<简短主题>/` 保存 `state.md` 和 `analysis.md`；防止覆盖同名的不同问题。无文件能力时在回复末保留同等含义的简短续接记录。不需要用户确认普通目录名称。

## 两份记录

`state.md` 保存当前问题与版本、原始困惑、用户明确的目标和边界、七阶段状态、最重要的来源指针、暂定判断、缺口、下一步与需要的现实反馈。

`analysis.md` 保存可检查的材料理解、各学科实际增加的分析、论证、交流文本、行动安排和带日期的反馈。文档很长时再拆成 sources、draft、review 等文件；没有内容不预建空目录或表格。

原始文件不改写；引用可用页码、段落、时间戳或用户消息位置。没有原页码就用稳定替代定位。状态摘要帮助续接，但不代替重读关键证据。

## 状态含义

| 状态 | 何时使用 |
|---|---|
| 已形成 | 本阶段所需产物已交付，可进入下一步；不代表所有主张已经被证实 |
| 暂定 | 有产物但依赖明确假设，可以在边界内继续 |
| 待补证 | 缺少会改变该判断的具体材料；标明哪些后续工作仍可做 |
| 待执行 | 有具体行动方案，尚无执行证据 |
| 待反馈 | 已定义观察或复盘条件，尚无真实结果 |
| 本次不展开 | 用户限制范围，或已说明此阶段当前无独立用途；不能默默遗漏完整请求中的阶段 |

七阶段可有不同状态，不能用一个“完成”掩盖等待现实结果。可以完成“本轮分析和行动准备”，同时明确“经验复盘等待反馈”。不要凭时间过去自动更新状态。

## 续接方式

用户带来新材料时先定位旧问题和新信息。对比原来的假设、判断、正文与行动，列出需要改变的部分，再只重做受影响阶段。新证据与原判断冲突时保留旧判断及其当时依据，添加修订原因，不能偷偷改写最初记录。

反馈记录可以很短：

```text
当时的问题与判断：
计划或预期：
实际执行与观察（来源）：
支持、反驳或仍无法区分的解释：
这次修改了什么：
下次可复用的做法与适用条件：
下一步及需要的反馈：
```

缺少结果时只填写已知部分，明确实际执行或观察仍未提供。合成案例仅用于演示，不混入用户经历。

## 收尾边界

交付当前可完成成果和下一次需要的输入。需要用户提供价值偏好或真实观察时说明它会影响哪个分歧；不要笼统要求“补充更多信息”。未授权的外部动作停在可审查草稿或计划，不将整个分析一起搁置。

建议下次回看时间可以写入计划，但不得说已安排自动提醒。若用户明确请求提醒或持续跟进，另按当前环境实际的自动化工具办理，并记录工具确认的结果。
